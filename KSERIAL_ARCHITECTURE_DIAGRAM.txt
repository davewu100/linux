DETAILED: BTF Resolution Process
=================================

Input: field_name = "level"
                │
                ▼
        ┌───────────────────────────────────────────────┐
        │  BTF (BPF Type Format) Database               │
        │  Auto-generated from kernel source            │
        │                                               │
        │  Type ID 1234: struct cgroup {                │
        │    member[0]: {                               │
        │      name_off = 5678  → "level"               │
        │      type = 890       → s32                   │
        │      offset = 576     → bit 576 (byte 72)     │
        │    }                                          │
        │    member[1]: {                               │
        │      name_off = 5690  → "nr_descendants"      │
        │      type = 891       → int                   │
        │      offset = 768     → bit 768 (byte 96)     │
        │    }                                          │
        │    ...                                        │
        │  }                                            │
        └───────────────────────────────────────────────┘
                │
                │ Linear search through members
                │ Compare name with "level"
                ▼
        Found: offset=576 bits, type=s32
                │
                ▼
        Calculate: byte_offset = 576 / 8 = 72
                   size = sizeof(s32) = 4
                │
                ▼
        ┌──────────────────────────────────┐
        │  struct cgroup instance          │
        │  Address: 0xffff888012345000     │
        │                                  │
        │  Offset 0:   kn (kernfs_node*)   │
        │  Offset 8:   self (css)          │
        │  ...                             │
        │  Offset 72:  level = 2      ◄────── Read from here
        │  ...                             │
        │  Offset 96:  nr_descendants = 5  │
        │  ...                             │
        └──────────────────────────────────┘
                │
                ▼
        value = 2 (int32)
                │
                ▼
        Encode as TLV:
        ┌────┬────┬────────┐
        │ 0  │ 4  │ 0x02   │
        └────┴────┴────────┘
         fid  len  value


TLV ENCODING FORMAT
===================

Binary Layout:

  ┌─────────────────────────────────────────────────────────────┐
  │  struct ks_result                                           │
  ├─────────────────────────────────────────────────────────────┤
  │  [total_len: 4 bytes]                                       │
  │  ┌────────────────────────────────────────────────────────┐ │
  │  │  TLV Entry #0                                          │ │
  │  ├───────┬───────┬──────────────────────────────────────┐ │ │
  │  │ fid=0 │ len=4 │ value (4 bytes): 0x00000002          │ │ │
  │  └───────┴───────┴──────────────────────────────────────┘ │ │
  │  │                                                         │ │
  │  │  TLV Entry #1                                          │ │
  │  ├───────┬───────┬──────────────────────────────────────┐ │ │
  │  │ fid=1 │ len=4 │ value (4 bytes): 0x00000005          │ │ │
  │  └───────┴───────┴──────────────────────────────────────┘ │ │
  │  └────────────────────────────────────────────────────────┘ │
  └─────────────────────────────────────────────────────────────┘

Parse Algorithm:

  offset = 0
  while offset < total_len:
      tlv = (struct ks_tlv *)(data + offset)
      field_id = tlv->field_id
      len = tlv->len
      value = tlv->data[0..len]
      
      print(schema.field_names[field_id], "=", value)
      
      offset += sizeof(struct ks_tlv) + len


SECURITY: Whitelist Model
==========================

  User Request: "Give me field 'X'"
        │
        ▼
  ┌─────────────────────────────────────┐
  │  Whitelist Check                    │
  │                                     │
  │  static const char *whitelist[] = { │
  │    "level",                         │
  │    "max_depth",                     │
  │    "nr_descendants",                │
  │    "nr_dying_descendants",          │
  │    "max_descendants",               │
  │    NULL                             │
  │  };                                 │
  │                                     │
  │  if (field NOT in whitelist)        │
  │      return -EPERM;                 │
  └─────────────────────────────────────┘
        │
        ├──► Field in whitelist: Continue
        │
        └──► Field NOT in whitelist: Reject (-EPERM)


Why whitelist?
- Prevents accidental information leakage
- Explicit about stable ABI contract  
- Easy to audit what's exposed
- Fails closed by default (secure)

  BTF Type = ?
        │
        ▼
  ┌────────────────────────────────┐
  │  Type Checker                  │
  │                                │
  │  switch (btf_kind(type)) {     │

COMPARISON: Traditional vs k-serial
====================================

Traditional Approach (Hardcoded Offsets):
──────────────────────────────────────────

  Source Code              Binary              Runtime
  ═══════════              ══════              ═══════
  
  struct cgroup {          offset 0x48         *(int *)(cgrp + 0x48)
    ...                    = level             = ???
    int level;    ───►     
    ...                    Kernel 5.15         Breaks on 5.16!
  };                       

  Problem: offset changes across kernel versions


k-serial Approach (BTF-based):
───────────────────────────────

  Source Code              BTF Database        Runtime
  ═══════════              ════════════        ═══════
  
  struct cgroup {          type_id=1234        1. Query "level"
    ...                    member[0]:          2. BTF lookup → offset
    int level;    ───►       name="level"      3. Read at offset
    ...                      offset=576 bits   4. Return value
  };
                           Works on ANY        ✓ Version-safe!
                           kernel with BTF

EXTENSIBILITY
=============

Current (MVP):
  struct cgroup → ["level", "nr_descendants"] → values

Future Phase 2 (Nested):
  struct cgroup → ["css_set.dfl_cgrp.level"] → value
                   └─► ptr → struct → field

Future Phase 3 (Arrays):
  struct cgroup → ["node_stat[2]"] → value
                   └─► array[index]

Future Phase 4 (Generic):
  ANY struct → ["field1", "field2"] → values

Future Phase 5 (Filtering):
  struct cgroup → filter: "level==2", aggregate: SUM
                   └─► complex queries


SUMMARY
=======

k-serial provides:
✓ Version-safe field access via BTF
✓ Selective field queries (not full struct dump)
✓ Type-safe (BTF validates types)
✓ Secure (whitelist + type validation)
✓ Efficient (binary TLV, batch queries)
✓ Simple (no BPF, just read/write)
✓ Multi-language (C, Python, shell, ...)

Perfect for:
- Monitoring tools
- Debugging utilities
- Metrics exporters
- System introspection

Not for:
- Performance-critical hot paths (use direct access)
- Complex pointer chasing (use BPF)
- Write operations (use proper APIs)
